# Lessplain 设计方案

本文约定产品行为和后续范围。使用方法见[根目录 README](../../README.md)，产品背景见 [context.md](../context.md)，现行工具参数见 [MCP 协议](../../skills/lessplain/references/protocol.md)。

## 目标与边界

围绕用户的问题，用关系图、真实源码和必要的解释帮助理解代码，并能在几天后回到原处。

- 图帮助找到关系和阅读入口，每个有源码依据的节点都应能返回对应代码。
- Agent 负责分析和生成材料；插件负责校验、保存与呈现。沿用用户已有 Agent，不内置模型配置或完整聊天系统。
- 区分事实、推断和未知。教学示例与模拟不能冒充运行观测，定位成功不代表旧解释仍然成立。
- React 原型仅验证交互，不代表真实 IDE、Agent 或 Debugger 能力。

## 阅读与导航

Understanding 是主工具窗口，标题栏保留教程、历史和在编辑器打开。没有有效画布时显示历史页。最后画布及追问路线按项目保存，恢复服从用户后续导航；编辑器标签活动和历史页不覆盖工具窗口的路由。

用户可主动将图打开到编辑器，不为每个问题自动创建标签页。两处查看同一记录与版本，路径、视角和布局按逻辑图层保存。编辑器中的源码自动跳转开关独立管理，明确打开图时默认关闭；工具窗口保留自己的跳转状态。

图内提供前后步、补全来路、全图、缩放和整理。控制流、调用、数据流、结构、依赖均可沿已有关系阅读；多条候选由用户按节点或精确边选择，不自动挑第一条。选路只改变候选和高亮，其他关系继续显示。取消选路不清除已经确认的路线。

每条历史根图及节点追问图分别保存当前节点、路径、视口、布局方向和手动位置。固定源码跳转与自动跟踪视口是独立开关。重复点击已选节点可再次定位源码，普通状态同步保持去重。

普通源码保持原样。当前节点只在有效依据处显示简短提示，悬停时高亮关联范围；切换节点清理旧提示，不累计已访问装饰，不压暗其他代码。图节点的业务起止和结果色来自源码语义，不能仅凭入度、出度猜测。

图布局由插件计算，Agent 不提交坐标。可选语义分组用于表达阶段、分支或子流程；共享节点只放一次，跨组连线保留完整关系。节点追问共用一张画布，每条问题的回答对应一个分组。拖动与整理保留当前阅读方向，整理只清除当前方向的手动位置。

## 提问、回答与回看

图节点可保存待答注释；源码选区提问固定当时的节点、记录版本、阅读路径和选区。用户切换文件或继续浏览，不改变已保存的问题来源。源码提问框只显示输入，靠近所选代码定位，见[定位规则](source-question-position-2026-10-27.md)。

插件保存问题并提供可复制载荷，由用户交给已有 Agent。复制不表示已经发送或回答，不通过长轮询维持 Agent 会话。未来有正式任务交接能力时，只替换宿主适配层。

流程和调用关系用理解图回答，概念学习可使用教程。独立且一句话能说清的答复可留在 Agent 对话。创建图或教程与完成已有问题是两项操作，Agent 使用问题 ID 明确提交答复。

普通读取不消费笔记、问题或反馈。批量处理固定最初范围，期间新增的问题留到下一批；显式消费反馈只清理指定 ID，其他源码问题保留。具体工作流由[配套 skill](../../skills/lessplain/SKILL.md)维护，不在设计文档重复参数示例。

有追问的节点通过“？”进入子层级；层级菜单可返回祖先或其他分支。回答分组标题旁的问号气泡回看该问题及冻结代码，根图问题入口位于图标题旁。已打开内容固定，显式打开另一个问题才切换，不读取当前源码补造历史。

历史按根记录组织，可搜索标题与问题。蓝点表示有未读，打开相应记录定位具体回答；重启后的旧未读由用户主动打开。理解记录整树删除，教程及问答删除范围见[删除规则](navigation-and-deletion-2026-10-27.md)。

## 实现与数据约束

界面直接使用原生 Swing 与公开平台组件，图表使用 ELK 布局、Java2D 绘制；Markdown 块解析使用 IDE 内置 Markdown 插件的公开入口。无需 Diagrams、Compose 或 Jewel 运行依赖。

理解模型、存储、IDE 适配、呈现和 MCP 分开。数据库与源码定位不阻塞界面线程；读取可取消，发布前检查来源、版本和生命周期。已确认的持久化操作独立完成，关闭后不回调界面，见[线程与生命周期](platform-integration-threading.md)。

- 节点、边及来源有稳定身份。问题归属与实际提问来源分别保存，失效来源不能替换成当前选择。
- 新建与修订分开，修订校验版本；成功重试重放原结果，迟到请求不能覆盖新状态或恢复已删除内容。请求标识由工具生成，Agent 不手算哈希或 UUID。
- 图及依据按项目保存在 SQLite。教程内容、资源、批注与所属回执作为原子快照保存，阅读状态独立。第二个 IDE 实例只读。
- 保存失败明确报错，不能返回成功。用户的历史与笔记不是可随意清理的缓存，不自动删除旧实验数据。

## 后续能力

以下是产品目标，尚未作为真实插件能力交付。

### 真实运行记录

静态探索表示可能路径，运行回放表示一次真实执行，两者分别保存进度。Runtime 是有序事件序列，同一节点可多次命中，不能简化为节点的一个最终值。

记录需绑定图、源码版本及执行身份，保留顺序、完整性和每次命中的值快照。回放只显示游标及之前的值，缺失事件明确显示间断，顺序号不能充当跨线程因果证据。先验证单线程、单调用，再扩展并发和增量采集。

显示源码位置与实际观测位置分别保存。求值必须发生在变量进入作用域且计算完成之后，不能机械使用下一行。到达保存调用不等于已落盘。教学模拟继续与真实 Trace 分开。

### Diff 与证据变化

先固定比较的两个版本，再按变化选择原生 diff 或局部关系图。图与 diff 双向定位，保留左右身份；删除节点指向旧版本，新增节点指向新版本，匹配不可靠时分别展示。

“改了什么”“可能影响什么”“为什么改”分别取证。影响需要结构或运行依据，动机需要提交说明或作者解释。定位状态与证据变化状态分开，手动修复位置不能代替重新分析；旧图和 Trace 不能自动套到新代码。

### 项目图与目录说明

原生 Project Tree 提供物理结构，项目图补充覆盖整个项目的语义关系，仍属于首个完整版本的目标范围。聚合、缩放与筛选只调整细节，不缩减分析范围；未分析和排除区域明确标记，不能用局部图冒充全貌。

IDE 提供模块、依赖与引用事实，Agent 归纳职责并保留成员范围及依据。证据不足时保留物理结构。目录职责说明尽量短，独立开关放在右键菜单；隐藏不删除分析结果，源码变化后提示核对。

### 验收顺序

先验证“看源码或 diff → 看关系 → 继续提问 → 回到原处”，再扩大规模与采集能力。全局图须用完整目标工程验收，记录覆盖范围及布局耗时，不能以单模块截图代替。

UI Outline 延后。修改参数后的实际效果交给项目自己的 Hot Reload 或 HMR，插件不自建跨框架 Preview 或 Renderer。
