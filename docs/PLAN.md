# Lessplain：真实插件基础实施计划

本文保留启动阶段的计划及选型过程。当前实现以 [README](../README.md) 为准；下文关于原生 Diagram、单一浏览状态和旧运行配置的条目是当时的计划，不代表现状。

## 目标与范围

在本插件工程中继续开发，打通：

**Agent 提交理解图 → 看图与定位源码 → 复制节点来源 → 用户提出追问 → 回答归回原处 → 重启恢复。**

开始前读取工程及上级的 `../../AGENTS.md`，以及 `docs` 下的 `code-understanding-design-v0.5.md`、`context.md`、`agents/implementation-draft.md`。产品要求以主设计文档为准，本批实施范围以本计划为准。

本批不实现真实 Trace、完整 Diff 理解、全局项目分析和目录说明。覆盖整个项目的全局图仍属于首个完整版本，本批不能被宣称为完整产品。不继续扩建 React 原型。

## 1. 先验证原生接入与 Jewel

- 保留现有 Kotlin／Gradle 工程和插件 ID。目标平台从 `2025.3.6.1` 调整至 `2026.1`，最低构建号为 `261`。按目标 SDK 核实构建工具链及运行环境。
- **优先验证 Jewel，不预先锁定全 Swing。** 使用目标 IDE 配套的 Jewel／Compose 与主题桥接，按对应版本源码确认接口，不照搬独立桌面应用配置。
- 做一个最小真实界面：Jewel 展示记录列表及提问输入，原生 Diagram 展示自定义节点和关系。验证自动布局、分支交互，以及工具窗口和编辑器两种承载方式。
- 检查二者共存时的焦点、快捷键、菜单、主题、缩放和组件释放。验证通过后，本批记录、历史、提问界面使用 Jewel；图形保留原生 Diagram，IDE 菜单及源码导航复用平台能力。
- MCP 接入 IDE 自带的 `com.intellij.mcpServer` 扩展点。参考同级 `walkthrough-plugin` 的注册方式，不依赖该插件，不复制其等待或轮询机制。
- 若 Jewel 或 Diagram 的实际限制影响核心交互、兼容目标或维护成本，先提供复现证据和具体替代建议，再向用户确认。不能自行改为网页图、重写图引擎或维护两套完整界面。

## 2. 首批只暴露三个 MCP 工具

| 工具 | 本批职责 |
|---|---|
| `get_understanding_context` | 捕获当前来源，或通过 token 读取固定来源及相关问题、图和证据 |
| `present_understanding` | 创建独立理解记录，保存图并关联原问题 |
| `append_understanding_answer` | 保存补充回答及来源，不强制创建新图 |

历史查询与搜索先作为插件内部能力实现。`get_understanding`、`list_understandings`、`update_understanding` 后续按工作流需要增加，不注册空工具，也不把它们合并成万能操作参数。

实现要求：

- 图保存稳定节点／边 ID、关系类型、分支条件、锚点和证据，不接收坐标。区分控制流分支与依赖关系。
- `contextToken` 固定项目、来源和版本，后续界面操作不能改变它。默认归属来源问题；无来源时要求明确根记录或父记录，校验归属无环。
- 复制节点来源时保存固定 `contextToken`，载荷包含协议版本、记录和节点标识；Agent 收到用户问题后在回答写入事务中创建并关联 `questionId`。复制成功不能显示成“已发送”。
- 写入携带 `schemaVersion` 和 `requestId`；相同请求重试返回原结果，相同 ID 不同内容报冲突。跨项目和失效引用明确报错。
- 本批只创建记录和追加回答，不覆盖已有图。数据层保留不可变版本，为后续显式更新工具留出支持。

## 3. 界面、源码与保存

理解模型、存储、IDE 适配、呈现和 MCP 分开。Java／Kotlin 语义解析放入可选语言适配层，界面类型不进入持久化模型。

- 一个 `Understanding` 主工具窗口。初始显示最近记录，“历史”进入窗口内的历史页，可搜索问题和补充回答。
- 图可主动在编辑器中打开，两处使用同一记录与版本；不自动为每个问题打开标签页。
- 图内提供缩放、全图和探索前后步。逐步探索到控制流分支时等待用户选路，返回改选后重建后续路径；自由浏览不受限制。
- 图节点悬停提供“复制来源”，Agent 根据来源 token 和用户问题写回答案；简短回答与新图都归回原节点。源码选区的同类交接入口仍待实现。
- 恢复所选节点、图位置和静态路径。普通光标移动不切换记录，源码不留累计高亮。
- 锚点使用相对路径、符号签名、文本和版本。定位状态与证据状态分别保存，重复文本不自动视为同一位置。变化提示可查看旧证据与当前代码，并复制核对问题。
- 使用项目本地 SQLite，位置为 `.idea/code-understanding/understanding.db`，排除版本控制。保存全部插件问答、图版本、证据、固定来源及浏览状态，不保存外部完整聊天。
- 源码快照覆盖未保存编辑；事务涵盖数据与请求去重。迁移前备份，失败保留原库；保存失败不报成功。第二个 IDE 实例打开同一数据时只读。

不提供模拟回答、冻结上下文、内部归属参数或无效发送按钮。

## 4. 验收与交付

使用独立 Kotlin／Java 测试项目，验证：

- 三个工具通过真实 MCP 可调用；提交分支图后能自动布局、定位源码，并等待用户手动选路。
- 复制追问后切换文件，返回回答仍归属原来源；重试不重复保存，非法引用明确失败。
- 简短回答可检索，记录、来源和浏览位置经重启恢复；工具窗口与编辑器显示同一版本。
- 插入行、移动函数、重复语句、依赖变化和未保存编辑不会被错误认定为证据仍有效。
- 数据库故障、迁移失败和第二实例只读行为符合约定。
- Jewel 与 Diagram 在深浅主题、键盘、焦点、菜单及关闭重开场景中正常配合。
- 完成相关自动化测试、插件构建及目标版本的 Plugin Verifier 检查。

开发实例使用 `Lessplain IDE`，单独打开插件目录时使用 `Lessplain IDE (standalone)`；旧的 `Run IDE with Plugin` 属于其他插件。两项配置运行 `runIdeLatest`，当前目标为 2026.2.3；编译平台与普通 `runIde` 保持 2026.1.5，最低兼容 build 保持 261。Verifier 分别检查 2026.1.5 与 2026.2.3。自动化检查不启动长期 IDE 进程；启动或重启调试仅使用 IDEA MCP。未完成的运行验证必须明确列出。

交付安装包、测试结果和简短验收说明，同步 README、设计文档的实现状态及配套 Agent skill。保留用户批注，不重复扩写规划，不把未验证能力写成已支持，不提交 Git。

## 2026-09-27 图实现调整

原生 Diagram 的 `DiagramBuilder.initialize()` 触发 Plugin Verifier 内部 API 门禁。GraphChart v2 虽可公开初始化，但无法通过已验证的公开接口读取最终连线路径并驱动沿线流动；直接调用布局器也抛出 `NotImplementedError`。已向用户说明证据并取得更换图实现的确认。图层现由插件自身的 Swing 组件布局和绘制，Jewel、记录模型、工具窗口与编辑器入口继续沿用。`test buildPlugin verifyPlugin --offline` 已通过；开发 IDE 中的动画、主题、键盘和交互仍须验收。

## 2026-09-27 追问层级与示例图调整

历史首页只显示顶层记录，子问题保留在所属记录和节点下。主图节点显示该节点追问数量；追问层中每个问题有独立大框，示例图直接呈现在框内。层级菜单提供返回，主图不常驻问答卡片。回答尽量用具体的输入→动作→结果示例，文字只补约束和依据。`present_understanding` 为追问保存子图；`append_understanding_answer` 供纯文字补充或修订。图布局增加分层、同层排序和孤立节点网格排列。完成后以当前登录流程和多追问节点验收视觉层级、返回恢复和节点标识；不以编译通过代替界面验收。

## 2026-09-27 追问簇修正

一个追问对应一个大框，示例图直接显示在框内。只有示例图节点实际拥有追问时，才可再进入下一层；纯文字回答在当前簇内按需展开，不生成空子层。层级路径收进画布内的树形菜单，默认折叠，编辑器中同样可用。`append_understanding_answer` 扩展 `replacesAnswerId`，允许对同一问题修订当前可见回答，保留原回答以供追溯。已用开发 IDE MCP 为 `request.getParameter("username")` 的原追问写入具体参数示例图；新界面与修订参数须重启开发 IDE 后验收。

## 2026-09-27 共享追问画布与节点操作

修正固定高度子图被裁切的问题：同一父节点的全部追问使用一张可缩放、平移的大画布，一条追问对应一个包围整个流程的 cluster；画布工具栏的统一导航按钮可跳到任意 cluster。开始节点用绿色、结束节点用警告红色，聚焦只突出边框。节点悬停时才显示复制固定来源与“？”入口，复制载荷包含 `contextToken`、记录和节点 ID；移除工具窗口底部独立的提问输入框。Agent 用来源 token 和用户问题创建子图时，`present_understanding` 在同一事务中保存并关联问题。`getParameter` 示例在图旁显示虚构的 `HttpServletRequest` 属性及处理结果，选择流程步骤时高亮相关字段。待开发 IDE 重启后核对实际大小、层级菜单、悬停命中和剪贴板来源。

## 2026-09-28 图层状态与源码提示

图表增加独立的“固定源码跳转”和“自动跟踪节点”开关；前者控制是否打开、聚焦源码，后者控制选节点时是否移动画布。源码提示只附着在当前节点的证据处，悬停时渐变高亮对应代码。每条历史根图和每个节点的追问图按记录及节点 ID 分开保存开关、路径与视口；工具窗口和编辑器使用同一份项目本地状态。追问画布的节点 ID 改为基于问题 ID，避免新增问题时旧节点改号。切换“最近”时重建 Swing 图表，避免只换标题。自动化测试和编译已通过；这些交互改动仍需在新构建的开发 IDE 中复验。

## 2026-09-28 步进、画布整理与开发 IDE

追问画布按连通分量寻找路径起点，恢复保存的边时以其所属 cluster 为起点；节点在回答数据中乱序时也从有出边的入口开始。无法前进或后退时禁用对应按钮。层级菜单进入图内工具区，在编辑器和工具窗口共用；节点可拖动，连线实时重算，位置按每张图独立保存。一键整理清除该图的手动坐标并显示全图。开发实例改用独立的 `runIdeLatest` 任务运行 2026.2.3，编译仍用 2026.1.5，最低兼容构建号仍为 261。自动化测试通过，离线 Verifier 判定两个目标 IDE 均兼容。新 IDE 中的菜单层次、拖拽和切换层级仍需目视验收。

## 2026-09-28 深层追问导航修正

层级菜单从根记录递归列出所有有追问的节点，不再止于当前路径；工具窗口与编辑器都能直接前往更深层和同层分支。步进器对 `data_flow` 的可走性不再依赖 `example` 节点类型。旧规则使深层 `input → step` 图的第一步不可前进，分支节点也无法退回输入节点；调试器已在同结构回归图中确认运行时可走边被过滤。新增深层步进和完整追问树回归测试。
