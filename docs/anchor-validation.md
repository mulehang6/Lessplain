# Lessplain 源码锚点与关系依据

本文记录插件实现与协议补充。用户 Agent 的工作流由独立分发的 skill 管理，本仓库开发要求见 AGENTS.md。

## 提交与保存

公开协议仍为字符串 `"1.4"`。上下文的 `capabilities.anchorValidation=true` 表示提交图会按当前 IDE 文档校验源码锚点，包含未保存编辑。节点、证据和证据依赖中的所有锚点都必须有效；节点也可通过已有 `evidenceIds` 定位。

- `version` 可省略，由插件计算完整文档 SHA-256；提供时必须匹配校验快照。旧 Agent 仍可提交版本。`lineHint` 只作提示，保存为实际一基行号。
- 路径必须在项目内，片段必须唯一，符号必须匹配。校验失败一次列出引用、路径和原因，不创建图、不修订原图、不删除待答注释。
- 成功响应增加 `resolvedAnchors=[{reference,path,line}]`。引用覆盖节点直接锚点、证据锚点和依赖锚点；行号来自已保存快照。
- `requestId` 的哈希使用补齐前的输入。成功重试返回首次保存的结果，不因之后源码变化而重新校验。源码读取在 SQLite 写事务外，事务内再次查重。

这项校验只验证源码引用，不证明 Agent 对调用条件、业务职责或修改动机的解释正确。

## 回到旧源码位置

旧片段仍存在时沿用文本定位；只有文本消失才按同文件符号查找函数。唯一函数可跳转，多个候选不猜测；签名不足以可靠区分重载时也保留歧义。

函数回退表示 `RELOCATED + CHANGED`，显示“仅定位到所属函数，原片段已变化”，不高亮猜测的逻辑块，也不显示旧 inline。原证据文本及版本保持不变。当前编辑片段发生变化时清除已有 inline，图和回到源码的入口继续保留。

## 推断关系

`capabilities.inferredEdges=true` 时可提交边字段 `inferred: true`，并用非空 `coverage` 写明依据。推断边使用轻微虚线；未提供字段的旧图保持原样，不根据 coverage 的文字猜测关系性质。普通边和候选边悬停时均可查看条件和 coverage，已有路径动画及分支选择继续可用。

## 本地存储

数据库位于 `.idea/lessplain/understanding.db`，写锁位于同目录。项目尚未发布，此次直接切换路径，不读取或迁移旧目录，也不自动删除旧文件。历史实录保留当时真实名称和路径。
