# Code Understanding Plugin 设计方案

本文是唯一主设计文档。React 只验证交互，不代表真实 IDE、Agent 或 Debugger 行为。`..` 已开始原生插件实现；当前实现及未验证项见根目录 README，不把代码编译通过视为完成交互验收。

早期技术建议和选型记录见 [实施草案](agents/implementation-draft.md)；当前实现状态以根目录 README 为准。

## 1. 目标与原则

围绕用户的问题，用图、真实源码、diff 和运行事实帮助理解代码，减少额外阅读，几天后还能回到原处。图帮助找关系、选阅读入口，不能代替源码。

- 尽可能开箱即用，沿用 JetBrains 的操作习惯。按钮用途和下一步应当直接可知。
- 先考虑长期使用，再安排分阶段验证；发现提议有问题要说明理由。
- 文档和解释尽量短。默认给必要结论，复杂关系用图，细节在需要时展开。
- “按需展开”指变量明细、证据列表等；历史、提问、返回和变化处理入口必须容易发现。
- 保留事实、推断与未知的区别，不以示例或图的完整外观冒充证据。
- Agent 分析并组织理解；插件验证引用、保存、呈现和回放，不另建模型配置或完整聊天系统。
- 不把 AI Chat、Air 或任何单一 Agent 宿主当成架构前提；宿主只负责承载 Agent，会随 JetBrains 的 agentic 形态演进。

## 2. 一个主窗口

Understanding 工具窗口容纳问题图、项目图和历史页。没有活动画布时显示欢迎页，按新增与更新区分未读结果，并列出最近记录；重新打开工具窗口保留已有画布。工具窗口可见时直接呈现新结果，不弹系统通知；隐藏时才提醒。“主页”“最近”“历史”和“在编辑器打开”位于工具窗口标题栏。

问题图和项目图均支持用户主动打开到编辑器区域。两处查看同一份理解记录，不能产生相互冲突的副本；不自动为每个问题打开标签页。具体同步和布局需在真实 IDE 中验证。

原生 Project Tree 负责文件结构，原生编辑器负责源码和 diff。点击节点定位代码，普通光标移动不自动切换问题。返回时保留图位置、所选节点和浏览进度。

编辑器保持安静：未选中的普通源码不加装饰。选中带有效锚点的图节点时，只在对应代码处显示一条简短提示；悬停提示才高亮关联代码。切换节点时清理旧提示，不累积已访问标记，不压暗其他代码。历史路径留在图中。

每张图分别保存浏览位置与交互开关。历史记录的主图、该图某个节点的追问图、另一条历史的图互不覆盖。固定源码跳转只阻止图的操作抢走源码焦点；关闭自动跟踪只阻止图的视口随当前节点移动，两项独立。

一个主窗口是产品选择，平台并无限制插件只能注册一个窗口。参见 [JetBrains 官方文档](https://plugins.jetbrains.com/docs/intellij/tool-windows.html)。

## 3. 看图与沿路探索

图中保留短职责、条件和必要值。前后步、全图、缩放位于图内工具栏；分支选择靠近分支。去掉重复描述图的常驻事件列表和源码说明面板。

|      | 静态探索           | 运行回放         |
|------|--------------------|------------------|
| 路径 | 选择研究的可能路径 | 已记录的运行经过 |
| 分支 | 用户选路           | 遵循记录         |
| 值   | 常量或注明的假设   | 对应命中的历史值 |

默认可以自由选节点。沿流程逐步探索时：

- 到条件分支停下，在边或目标节点显示条件，让用户直接选路，不弹对话框、不替用户选第一条。
- 可返回改选，重建该分支之后的探索进度；循环可再看一轮或离开，不无限复制节点。
- 项目依赖、调用关系的多条连线，不自动当作互斥分支。
- 条件或覆盖范围未知就说明未知。选路不证明可达，也不生成真实变量值。

回放共用一个进度位置。重复节点默认只显示命中次数，选中后在节点旁展开“第几次”；选择某次命中会带动整张图回到那一步，不增加文字事件面板。值随进度变化，不提前显示未来结果。

静态的下一步沿所选关系前进，回放的下一步前往下一次命中，两者分别保存进度。研究没执行的分支时切换到静态探索，原记录保持不变。

关键动作支持键盘，不只靠悬浮发现；业务起止由 Agent 根据源码显式指定 `flowRoles`，不增加起止标签或图标。起点蓝色；结束结果通过可选 `endOutcome` 表达，success 绿色，failure 红色（包括预期拒绝），未知或混合结果保持 null 并显示中性色。双角色使用蓝底与对应结果色边框，不把恢复后的异常标为失败结束。分支表示当前图有多个可浏览去向：插件按 control_flow、call、data_flow 的不同后继数大于 1 计算，入度不参与，同目标平行边只算一个后继。不由 Agent 提交 decision；在文字前显示与文字等大的橙色分叉图标，保留矩形卡片和半个字宽的间距。聚焦和悬停使用外圈反馈。协议仍为 3，Agent 仅在上下文明确返回 capabilities.nodeSemantics=true 时提交 endOutcome。

静态探索保存实际走过的边，不从图入口重建路线。下一步及选路追加边，上一步原路退回；点击当前节点保持路径，点击路径内节点回到最近出现的一步，点击路径外节点从该处开始新路线。节点、路径、高亮及源码提示使用一致状态。恢复时仅接受连续且终点匹配当前节点的路径，不匹配则从所选节点重新开始。

## 4. 从 diff 理解变化

入口可以是一次提交、工作区变更，或旧理解对应的代码发生变化。先固定比较的两个版本，再围绕一个具体变化查看关系和代码，避免一开始生成整仓大图。

| 变化 | 合适的呈现 | 如何落到代码 |
| --- | --- | --- |
| 判断、调用顺序改变 | 同一布局切换修改前后，标出改变的节点和边 | 点变化处打开对应 diff 片段 |
| 跨文件职责或依赖改变 | 展示变更区域及有依据的直接关联，可继续展开 | 点关系查看调用、引用或配置依据 |
| 少量文字、常量或说明修改 | 原生 diff 加一句必要解释 | 直接阅读改动，不强行画图 |

图与 diff 双向定位，保留左右版本身份。删除的节点打开旧版本，新增的节点打开新版本；匹配不可靠时分开展示，不能把名称相似当成同一节点。

“改了什么”“可能影响什么”“为什么改”分别取证。影响依赖结构或运行依据；修改动机需要提交说明、讨论或作者解释，只有 diff 时可以不知道。前后运行对比还需注明输入和环境，不能把条件不同的两次运行当成效果证明。

例如 diff 只显示 jbcontext 的使用说明被删除，就不能证明工具已卸载、能力已失效或存在替代方案。这里先看文本更合适；若要理解它与 Agent 找代码的关系，再补有依据的关系图。

## 5. 在不懂的地方继续问

图节点、源码、diff、解释中的术语使用一致的“提问”入口。用户选中 jbcontext，可以问“它是什么”“在这里做什么”“为什么删这段”，也能输入自己的问题，不局限于预设选项。

目标流程，须先验证与已有 Agent 的任务交接；交接不能依赖 AI Chat 的具体实现：

1. 选中对象后就地输入一个问题，插件立即保存 `questionId`、`contextToken` 和来源，不要求手动复制文件名和位置。
2. 若当前 Agent 宿主提供稳定的任务交接能力，插件只做一次 handoff；没有则生成可粘贴的问题载荷，由用户提交到自己的 Agent。
3. 插件不驻留等待 Agent，也不通过长轮询维持会话。回答通过 MCP 带回 `questionId`，到达后挂回原来源；用户期间可继续浏览。
4. 图节点上的追问从悬停时显示的“？”进入子层级。该节点的全部追问共用一张画布，一条追问对应一个包围其流程的 cluster；画布内统一导航按钮可跳转 cluster。只有图节点实际拥有追问时才显示“？”。返回时恢复原节点、视口和路径。

沿已有图继续追问时保存问题、图和来源。插件不保存纯文字回答；无需嵌套的独立极短答复留在 Agent 对话，不创建理解记录。历史页按根图组织，可搜索并回到原处。

待答节点注释默认一次处理当前理解图及其后代追问，排除其他理解图。上下文返回队列快照，每项绑定自己的 questionId、原问题、来源节点与固定 token，并提供所属记录的当前图；不要求逐条选择待答。Agent 逐项核对源码并提交回答图，保存成功与删除独立注释条目在同一事务中完成。原问题和来源保留在回答图中，不另存已回答注释历史；失败、被修改或证据不足的项继续保留，不能用清空代替回答。结束时按最初范围复查本次队列，不随画布自动切换扩大范围；期间新增注释留到下一批。插件提供队列，不自动启动 Agent。

注释编辑使用支持中文 IME 的原生文本组件，字体跟随 IDE 外观设置。文本区固定宽度，从一行起按换行与折行增高或缩回，最多 8 行并受可用屏幕限制，之后内部滚动；通过公开 JBPopup 的顶部标题区域移动，内容变化保留位置。非空草稿在当前画布内暂存，常驻显示同一气泡；只有草稿时点击直接续写，与已有注释共存时提供继续编辑入口。保存或取消后更新图标，空草稿不显示；画布销毁清理草稿，保存前不进入 Agent 队列或已保存注释数量。

历史首页只列顶层理解记录；子图归属父图，搜索命中子问题时仍能回到所属记录。删除确认使用公开 DialogWrapper，由 IDE 绘制主题标题栏与标准按钮，初始焦点及默认动作为取消；Esc 和关闭窗口均取消删除，外部点击遵循平台模态对话框行为。单记录画布显示固定在视口内的紧凑标题、图节点和关系，不再绘制包围全图的 root cluster。标题与左上工具按钮同一行叠在画布内，不占独立高度；悬停或键盘聚焦时，小铅笔紧跟标题末尾并保留间距，支持双击及 Enter/F2 编辑。窄窗口截短标题，悬停显示全文，标题区域之外的图交互继续可用。同一节点的共享追问画布仍一问一组。节点悬停时，有追问图显示“？”，有待答注释常驻显示气泡，点击打开全文，同一按钮再次点击关闭，悬停不打开；右键可添加注释。注释展示与原生 IME 输入使用 IDE 外观 UI 字体，编辑器字体单独设置。层级菜单可返回祖先层。节点可拖动，一键整理保留当前横纵方向及方向偏好，只清除当前方向的手动节点位置。

回答先给一个具体输入、发生的动作和看得见的结果。例如 `request.getParameter("username")` 可画成“请求参数 `username=alice` → 按键 `username` 读取 → 局部变量得到 `"alice"`”。需要说明参数缺失时增加相应分支。图中的短标签和箭头标清值的流向，不把解释段落塞进节点。示例必须标为示例，不能冒充运行观测。凡保存到插件的回答都必须有图；只有独立且无需示例和过程解释的极短答复才留在 Agent 对话。

图布局以稳定阅读方向、同层对齐、少交叉和足够留白为准。控制流优先维持上下层次，调用关系不能把后继错误地排成并列独立节点。节点数量或窗口宽度变化时重新适配视口；布局由插件确定，Agent 不提交坐标。当前原生 Diagram 初始化受插件兼容性门禁限制，保留自绘图层并改进分层与交叉排序，不直接调用内部布局 API。

**修正旧约束：允许局部提问输入，但不另建一套完整聊天产品。** 用户继续使用已有 Agent 的能力。AI Chat、Air、CLI 或其他宿主都只是一种承载面；输入位置、回答展开方式和外部任务交接仍需验证，保持连续的阅读体验是目标。

当前插件没有 Agent 自动任务交接。节点悬停提供“复制来源”，用户可把来源 token 和问题一起交给 Agent；复制不显示为“发送”。MCP 工具负责接收 Agent 的结果，不能据此推断插件已经能启动 Agent 任务。

首轮先实现复制固定来源，Agent 收到用户问题后通过 MCP 返回结果；`present_understanding` 会在保存子图时补建并关联问题。不为就地提问引入驻留等待或长轮询。未来若 IDE 或其他 Agent 宿主提供稳定的任务交接，只新增宿主适配层，不改变问题、来源和结果协议。

## 6. 记录来源与代码变化

一份理解记录保存问题、图、证据版本、归属和提问来源。归属表达问题之间的关系，来源记录具体从哪里问起；小补充与新建问题要区分。挂错位置时用“移动到…”选择实际问题。

例如 A 是“分支流程”，B 是其下的“草稿恢复”。从 B 问起“谁有权限创建分支”得到 C：来源是 B，归属仍是 A，C 与 B 同级。

contextToken 可以理解为内部的“提问位置书签”。例如从 diff 中问 jbcontext 后切到别的文件，Agent 返回时仍能把答案挂回原来的 diff。它不是模型的 token 用量，也不需要用户操作。

就地提问时由插件在提交瞬间捕获来源；从 Agent 发起时，在读取插件上下文时捕获。来源包含所选对象、图或源码版本、静态路径或回放位置；diff 额外保存前后版本、文件和所在一侧的片段。

锚点使用文件、函数或类、文本和版本定位，行号只作提示。找不到或有多个候选时明确说明。位置找到了，不等于旧解释仍然成立。

跨函数仅找到相同文本时先列为候选，结合符号关系或重构证据才能确认迁移。文本未变也需核对解释所依赖的条件与调用；例如调用仍是 save(child)，被调用实现却可能由同步保存改成排队。定位状态与证据状态分别保存，未知不等于已确认有效，也不直接等于解释错误。

内部定位状态为 exact／relocated／unresolved／ambiguous；证据状态为 unchanged／changed／unknown。不能合成一个 stale 布尔值；unchanged 只表示核验范围内的证据未变，不证明全部语义正确。

“代码已变化”应能点开旧证据与当前代码，继续阅读或发起核对。手动确认位置只修复定位；重新分析才产生新理解版本。旧图和旧 Trace 保留各自版本，不能自动套到当前代码。

## 8. 实现约定

以下约定约束实现，不要求用户学习。详细参数在正式接口设计时确定，不能把接口示例当成已完成能力。

| 对象     | 必须保留的约定                                                                 |
|----------|--------------------------------------------------------------------------------|
| 图       | 节点、边有稳定标识与类型；控制流边保存条件和覆盖范围；布局由插件计算           |
| 来源     | contextToken 绑定项目、来源对象与版本；失效报错，不偷换成当前选择              |
| 问题归属 | 默认归入来源问题；明确指定才成为同级或根问题；无来源不静默建根；校验父级和无环 |
| 更新     | requestId 防重复；新建和更新分开，更新校验目标版本，迟到结果不覆盖新状态       |
| 锚点     | 项目相对路径、限定符号及签名、文本、版本、可选行号和指纹；用 PSI 解析与消歧    |
| 运行记录 | traceId、图和代码版本、执行链身份、完整性，以及有序的 nodeId + seq + 值快照    |
| 观测     | 显示位置与实际观测位置分别保存；未观测、求值失败、null 和实际值区分            |
| diff     | 前后源码快照、两侧锚点和变化对应关系；推断的影响与修改理由分别注明依据         |
| 目录说明 | 按范围和证据版本更新；支持多条短职责，显示偏好独立保存                         |

同一节点允许多次命中。回放只使用游标及之前的值；顺序号不代表跨线程因果，丢失处显示间断。首轮只验证单线程单调用，命中事件预留可选 executionContext，不展开并发模型。首版接收整份 Trace，新采集用新 ID；增量追加另定去重和结束规则。

采集表达式结果时，须确认计算已经完成，目标变量已进入作用域且可求值。源码显示位置与实际观测位置分别保存，验证调试器行映射，不能机械地选源码下一行。到达保存调用不等于保存完成或落盘。

读取上下文与呈现理解图的两个 MCP 工具已经实现，当前上下文可返回来源记录；原图修订使用呈现工具的 `placement=revise` 与当前记录版本。任意记录 ID 读回、提交运行记录、更新目录说明和呈现项目图仍待实现。节点注释保存为待答问题，Agent 读取当前选中目标后提交图；不依赖 AI Chat 私有状态，也不通过长轮询等待 Agent。复用已有 Agent，不重复包装 IDE 搜索或 Debugger。[配套 Agent 规则](../skills/understanding-frames/SKILL.md)负责工作流，插件负责数据校验。

按项目本地保存记录、版本和浏览状态，支持原子写入与格式迁移；失败保留旧数据。版本可以是提交或内容快照，覆盖未提交、未保存的编辑内容，不能只记录一个不断变化的“工作区”标签。按需采集变量，限制记录大小，不默认上传或因清理缓存删除问题历史。持久化可参考 walkthrough，但需核实其实现。

理解模型、IDE 适配、呈现和 Agent 协作分开。后台工作支持取消。React 不决定最终渲染技术，须在真实 IDE 验证主题、焦点、键盘、无障碍和性能。

平台最低目标为 2026.1，长期面向所有基于 IntelliJ Platform 的 JetBrains IDE；首批建议正式验证 IntelliJ IDEA 与 Kotlin／Java。图形交互参考 IDE 右键“图表”的原生 Diagram，优先验证框架复用；跨 IDE 可用性与工具窗口嵌入能力未验证前，不锁定图引擎。

## 10. 节点注释与流程分组的当前实现

节点注释仍是待答问题。有注释时气泡常驻，悬停显示完整文本，点击后固定预览；没有注释时，添加入口随节点悬停出现。预览可选择待答、编辑、删除和添加。删除只将待答问题取消，保留固定来源与已回答的子图，拒绝该问题的迟到回答。Agent 答复后，该注释从待答列表移入追问图。

最近列表和编辑弹层使用公开 JBPopup 承载 Jewel 内容，跟随 IDE 主题。注释支持多行、Ctrl+Enter 保存；Esc 或外部点击关闭保留草稿，取消丢弃，保存清除。草稿限当前画布生命周期，问题回答、删除或画布销毁后清理。标题有悬停、按下和选中反馈，点击铅笔或双击进入编辑。

复杂度由解释目标决定，不设节点数阈值。流程存在可独立说明的阶段、分支或子流程时，Agent 可提交单层语义分组；简单连续流程保持一组。共享入口与汇合节点只放一次，通过跨组连线保留完整关系。全部组始终显示在同一画布，导航聚焦组内目标并保留缩放，可随时显示全图。手工分组和嵌套分组未接入。

当前 MCP 仅接受协议版本 3。删除公开 `clusters` 字段和记录级语义多分组；节点新增可选 `flowRoles` 数组，取值只有 `start` 和 `end`，可同时具备两者。`kind` 保持类别职责，多个业务入口和出口均可显式标记。节点、边及固定来源的标识保持不变。无旧协议降级、旧记录迁移或自动删除，旧记录由用户自行清理。注释与标题编辑使用原生 IDEA/Swing 文本组件和公开 JBPopup，支持中文组合输入；保留主题外观、草稿、版本校验和资源释放。
