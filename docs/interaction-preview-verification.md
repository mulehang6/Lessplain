## 实现范围

- 横向输入使用实际 `deltaX`，Shift 滚轮兼容 `deltaY`，并换算行、页单位。实测 Windows OSR 的横向通道与 IDEA 原生编辑器相反，按实际 `isOffScreenRendering()` 导出符号校正，其他通道保持标准映射。可消费输入的原生滚动区域优先；纵向滚动、Ctrl 缩放和右键拖动画布保留。原始输入字段可在内部模式诊断或日志点中查看。
- Collapsible、Accordion 显式报告开关状态。自然内容与预留外框分开测量，按组件身份组成的折叠状态分别保存高度，最多保留 32 组。显式收起可缩回；同一折叠状态内的普通内容切换保留最大高度。关闭内容卸载以释放隐藏 iframe。整体内容替换重置缓存。
- 增长及收缩都按帧合并测量，锚定触发分组；普通 resize 不自动排版。逻辑宽度保持稳定，避免收起后把内框宽度误作外框宽度。
- JsonView 和 CodeExcerpt 使用紧凑入口，打开 IDEA 原生只读标签。CodeExcerpt 默认读取保存的源码，另有“定位当前源码”。页面数据、源码快照和教学代码使用不同来源类型；组件数据冻结当前值、状态、身份、摘要及 UTF-16 选区。
- 后端签发有界的组件快照，校验页面版本、组件版本、签发内容和选区。控件切换不改写已打开内容；关闭、删除、来源改版及项目释放使旧入口失效并释放资源。已保存问题保留当时的正文与状态。
- 缓存示例单独展示 key 和 Redis 类型，JSON 主入口使用已明确解析的对象，次入口保留原始文本。编辑器换行规范化后的 UTF-16 偏移与原始文本分别保存，不递归猜测字符串，也不删除反斜杠。
- Card、Badge 支持可选 `neutral / info / success / warning / danger`。轻背景、边框及标签承载颜色，正文使用正常前景色。catalog 和后端校验使用同一协议。
- context、三个 skill 和协议同步调整：按问题选择图、短文字或交互，保留源码核验、模拟数据标注、学习检查及教学职责边界。

## 运行证据与诊断边界

先通过日常开发 IDEA 的 MCP 启动准确的 `Lessplain IDE` 调试配置，在基线布置非暂停日志点。观察到页面 HTTP 200，以及 ready、select、browse 请求进入与完成。日志只记录方法、标识、代次及计数，不记录源码正文或问题内容。调试器求值会扰动时间，不能把日志点耗时当作性能基准。

使用 Computer Use 打开实际沙盒的既有 tag 页面，复现“源码入口”展开后边框增长、收起后仍保留原高度。实际折叠缺陷已经复现。该轮没有重现 renderer 退出，也不能据此排除随机卡死。源码修改后智能移动了一个旧日志点，产生了 `status` 不在作用域的求值错误；它不是 renderer 崩溃事件。旧 Agent 日志点已移除，用户断点保留。

内部模式现在每 2 秒批量回传最多 128 条数值时序，前后端各保留最近 120 秒且最多 500 条记录。可见页面超过 8 秒无心跳或收到 renderer 退出时，在后台保存异常快照到 IDE 日志目录的 `lessplain-diagnostics/`，最多 10 个自有文件及 50 MB。隐藏、初始化、休眠恢复和正常释放不报警；正常事件不逐条写盘。不上传记录，不修改 GPU、remote 或 OSR 设置。

Find Action 中的 `Lessplain: Open DevTools` 和 `Lessplain: Capture Browser Diagnostics` 应在加载插件的沙盒 IDEA 内使用。日常开发 IDEA 的 MCP 负责调试沙盒 JVM；内部模式不是日志点的前置条件。

新版沙盒实测打开了“页面数据 · ConfigDTO 字段示例.json”原生只读标签，显示冻结的 `tags: "1,3"`，componentCode 进入及完成日志成对，求值错误为空。源码入口展开后的分组下边界约 652px，收起后恢复约 564px，分组标题位置保持约 170px。未重写原始页面文档。

同一自动化横向输入 `scrollX=160`，在 IDEA 原生编辑器中内容向左，在修正前画布中内容向右；日志点采得 `deltaX=-132, deltaY=0, deltaMode=0, shiftKey=1`。这是符号适配的运行依据，不能据此声称真实触摸板和倾斜滚轮均已验收。参考本地 IDEA 的 `JBCefOsrComponent.processMouseWheelEvent` 与 `JBCefBrowserBuilder`，未根据 builder 请求值猜测实际是否 OSR。官方 SDK 文档未说明该符号差异，因此没有把它当作 SDK 保证。

最终包通过 MCP 重新启动后，加载日志确认 HTTP 200、`horizontalSign=-1`。相同 `scrollX=160` 仍采得原始 `deltaX=-132`，画布内容现在向左移动约 132px，与原生编辑器一致。拖动工具窗口分隔线使视口从约 670px 增至约 950px，再恢复，分组与镜头保持逻辑位置；展开宽度后的观察期间没有新增 layout 日志点事件。该轮求值错误为空，未观察到 renderer 退出。取证结束清除本轮 Agent 日志点，保留用户断点及已加载新版的沙盒，供继续验收。
