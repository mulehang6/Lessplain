# 多 cluster 排版修复与复杂链路交接

2026-10-01。保留前序未提交改动，本轮未提交 Git、启动 IDE、操作桌面或截图。工具恢复为内置 IDEA MCP 优先，未调用或启用 Index MCP。

## 排版修复

原布局给所有 cluster 按输入顺序补了一条隐藏串行关系。文章发布的搜索、统计、积分和站点地图消费者因此被依次放到下游，虽然源码中的事件关系是并列分支。单次 compound 布局还会为跨组连接分配组内空间，使只有一个节点的组出现大片空白。

现在先对每组内部节点和关系执行 ELK 布局，再按实际跨组关系排列尺寸固定的组。组的尺寸包含节点、组内连线、标签、标题、节点操作和示例面板的实际范围；跨组关系不会拉长组内布局。仅没有任何跨组关系的共享追问画布保留原记录阅读顺序。

跨组连线连接实际节点端口，避开无关组内部、标题、示例、节点和其他边的标签、箭头。普通正交候选无法通行时，通过可见通道网格查找折线路径；优先保留已验证的组内线路，再安排主线与稳定边 ID。继续复用现有圆角与路径动画，不改变节点、边 ID、记录或 MCP 契约。

## 更复杂的真实样例

在 tech-community 中新建「付费文章：双渠道与阅读解锁」，记录 ID 为 `0a7e78fd-3214-437a-9597-0e04576701a8`，revision 为 1。包含 41 个节点、50 条关系和 8 个组：发起购买、支付信息准备、个人收款码、微信支付、用户确认、回调汇合、异步通知、阅读解锁。

该链路包含两种支付渠道、用户确认与外部回调两个入口、终态与幂等检查、失败后再次购买、异步通知和后续独立阅读请求。分组对应不同职责与触发入口，适合验证分支、汇合及状态复用。阅读请求通过持久化支付状态关联回调，不把跨请求的数据关系写成即时调用；异步消费者的完成顺序没有保证。

每个节点的完整连续源码块、行号和文件 SHA-256 均已核对。已通过插件 MCP 保存，再只读核对数据库中该版本的节点、边、组、条件和源码锚点与提交内容一致。原文章发布记录仍为 revision 1，后台密码登录仍为 revision 3，没有改写它们。

回归资源只保存无源码、无本机路径的图形样例。非 `control_flow` 关系不得携带 `condition`，其说明使用 `coverage`；工程技能补充了此约束。

## 验证与交付

自动化覆盖两种方向下的分支并列、单节点组尺寸、输入顺序与确定性、文章发布与付费文章样例，以及汇合、平行边、回边、自环、示例空间和组内相对坐标稳定性。检查组间不重叠、组内绘制范围、无关组及节点避让、标签与箭头分离。

最终 `test buildPlugin verifyPlugin --offline` 成功：113 个普通测试全部通过，无失败、错误或跳过。两个显式性能基准通过；文章发布纵向/横向布局中位数为 64.35/11.53 ms，付费文章为 772.44/73.85 ms，普通 500 节点图为 683.83 ms。环境、采样和数据边界见 [性能记录](graph-layout-benchmark.md)。

最终 ZIP 为 23,005,445 字节。IDEA 2026.1.5（IU-261.27258.48）与 2026.2.3（IU-262.10968.63）均为 Compatible；分别保留 4/7 处 deprecated API、两版各 8 处 experimental API 提示，无兼容错误。本轮布局新增能力只使用 ELK 和内部几何处理，没有增加 IDE 内部 API。

工程技能 `quick_validate.py` 通过。

## 用户验收

安装 `build/distributions/master-understanding-1.0.0-SNAPSHOT.zip`，按平台要求重新加载插件。在旧文章发布记录和新付费文章记录中分别切换横向、纵向，再执行一键整理和显示全图，核对分支排列、跨组连线及组导航体验。

MCP 保存新图不会加载本次构建的插件代码。自动化几何回归不能替代真实 IDE 中的视觉体验，本轮没有进行实际界面验收。

## 后续用户反馈与单组对照

用户实际截图反馈：付费文章图仍有大量长跨组线，难以阅读。此前的几何、测试和兼容检查通过不代表视觉验收通过；当前多组排版尚未获用户认可。

按用户要求新建「付费文章：单组对照」，记录 ID 为 `e9c4a038-2a17-480b-bf85-73b48366cf29`，revision 为 1。41 个节点、50 条边、证据、源码锚点、顺序和原问题与多组版完全相同，全部节点放入一个 cluster。重新核对 12 份磁盘源码中的 42 个锚点，再通过插件 MCP 保存并只读核对落库内容。原多组版仍为 revision 1、8 个组。

本阶段只增加对照记录，没有修改插件布局代码或取消多组能力；是否保留最上层多组，等待用户比较实际效果后决定。


## 2026-10-02：产品决策替代

用户比较单组效果后决定移除记录级语义多分组与默认 root 框；共享节点追问的一问一组仍保留。协议升至 3，显式业务起止与原生 IME 编辑同步完成；上述历史排版记录不再表示当前公开功能。最新实现、验证和仍需用户验收的内容见 [单画布交接](single-canvas-ime-handoff.md)。
