# Lessplain Teach

围绕长期学习目标，每节教一个明确能力。沿用 teach 的主动回忆、间隔复习和根据表现调整难度的思路；借鉴 walkthrough 围绕场景、源码入口和下游调用组织短步骤的方法。页面与追问使用 Lessplain 协议，原 teach 的 HTML 资料保持独立。单次代码问题由 lessplain 处理；当前开发任务中的方案审查与追问由 annoy-me 组织。

仅在用户明确使用本技能开展教学时启动。普通开发请求、讨论技能设计或引用技能文件均不启动教学。

## 开始

先读取项目内已有的 .lessplain-learning/mission.md 和相关 learning-records，结合用户当前指定的主题选课。没有指定主题时，在本次主动调用内根据目标、实际回答和待复习点推荐下一小节。缺少关键目标时只问一个能决定范围的问题；改变已定 mission 前由用户明确确认。学习记录反映学习情况，项目事实仍由实际源码核对。

读取 [呈现协议](../lessplain/references/protocol.md)，再调用 lessplain_context。以其 catalog 为可用组件清单。已有 note: 问题必须按固定 question 和 origin 回答，保留来源选区和状态。

旧课程页面 ref 已失效时，保留 mission 和学习记录，说明无法恢复，再获取新 context 重建本节；不编造旧页面状态。工具不可见或提交失败时说明哪些材料尚未呈现，成功取得保存回执后再写入新页面 ref。

## 一小课

1. 明确本节结束后用户应能做什么，从具体用途或问题引出目标。项目代码适合入门时直接使用；过于复杂、缺少相关机制或没有项目实现时，准备只演示一个机制的短样例。逐节点核对代码和官方技术语义；项目事实仍须读取实际源码，缓存命中对应注解或拦截实现。备课核验每节执行，不要求每节都寻找项目代码或运行 trace。
2. 围绕本节场景串清入口、分支、状态变化和结果，让用户能从节点回到项目源码或教学样例。先辨认对象和职责，再引入关系；教学顺序不冒充执行关系。小样例理解后，按本节目标连接真实项目的对应位置和差异，没有对应实现就如实说明。
3. 在 Cluster 内组合必要交互，例如改变条件并观察状态或分支。共享状态驱动组件与 Graph.selectionPath 联动。sources、SourceLink/openSource 对应真实项目；codeSamples、CodeSample/openSample 对应独立样例，默认只读原生编辑器，不把代码长文塞进画布。需要亲自改动或验证运行时再准备 Scratch 或练习文件；不默认新建文件或实现执行器。
4. 调用 lessplain_present 提交完整页面。真正的流程用 Graph；并行概念可无连线；JSON 与字段比较用组件；需要自定义操作时使用 Demo。
5. 提供一次可跳过的学习检查，例如先预测路径再揭示结果、解释一个新输入，或完成一次小操作。检查针对本节能力，呈现题目时保留待判断结果；根据用户实际回答给出具体反馈。跳过不阻断后续浏览，只记录为看过。学习检查与源码核验分别执行，不能互相替代。

示例的行为与真实项目事实分开标注。模拟命中、虚构 ID 或演示名称是练习数据；只有实际读取/观察到的实现才能写成事实。推演可作为默认教学材料，标为演示；需要确认具体调度、变量、异常或取消效果时再获取真实运行证据。静态分析得出的可能路径不能写成已发生的运行记录。

每个小课围绕一个能力，用带短标题的 Cluster 放置各组对照和操作，节点只保留短句。操作和字段放在 companion，图放在 diagram；同组通过 Graph.selectionPath 联动。所有分组共用画布；独立对照可分组并列，有真实关系才添加 Board.edges。通过普通组件选择和显隐控制当前信息量，保持布局稳定；不增加画布外说明文章或通用详情层。

连线只标必要的短条件，参数和重复动作说明放 summary 按需查看，不把步骤解释常驻在线上。节点与关系 ID 在修订时保持稳定。

## 继续与回顾

重新进入已有 ref，提供一次回忆机会，再恢复必要的上次状态。用新输入或条件变化检查能否迁移，结合上次记录调整难度。一次即时答对只说明本次检查通过，复习时再观察独立回忆与应用；没有回答不推断学会。

插件保存页面、问题和示例状态。Agent 在用户项目的 .lessplain-learning/ 中维护简短 mission.md 和递增 learning-records：记录本节能力、页面 ref、已核对的来源、用户实际回答或跳过、反馈依据及下次复习点。明确区分看过、本次检查通过与需复习；先记录观察，再写学习判断。已有资料直接复用，只创建本次需要的文件。

用户可在 Agent 对话回答，或从插件注释入口提交问题后复制回来。按固定引用读取和回复，保存回执成功后再更新相关学习记录。Agent 在正常对话回合继续教学，插件负责保存与呈现；不需要常驻等待工具或后台自动安排课程。

## 提交前检查

能直接回答用户原问题；涉及的新名词已能辨认；源码引用足够具体；示例值有标注；组件状态操作有明确学习目的。对“是什么”不强行添连线，也不附带与问题无关的修改流程。

工具失败时修正输入并验证保存回执。skill 约束工作过程，不能保证 Agent 每次都作出正确解释；缺乏源码证据时如实保留不确定性。
