# Lessplain

处理当前代码问题及其追问。持续课程、跨会话学习目标和复习记录由用户主动调用 lessplain-teach；当前开发任务中的苏格拉底式讨论由 annoy-me 组织。

使用当前项目的 IDE MCP；源码读取方法按宿主和项目规则选择。工具不可见时说明缺失，不宣称保存成功。调用路由器时，目标项目的绝对路径放在外层 projectPath，工具参数按路由器的实际 schema 编码。

## 固定上下文，再提交完整页面

1. 调用 lessplain_context。新独立问题省略 ref；继续处理时传插件提供的 view:、note: 或 source: 引用。
2. 保留返回的 context、question 和 origin。界面后来切换不改变问题来源。已有 question 时保持原话。
3. 读取实际源码，区分事实、推断与示例。用返回的 catalog 选择组件并构建 spec。
4. 调用 lessplain_present(context, view)。view 包含 question、spec，以及可选 title、sources、demos、codeSamples。创建和更新使用同一工具；spec 是完整替换，省略的组件会移除。
5. 保存成功才说明已呈现；失败根据错误修正。同一 context、相同内容可重试；内容改变或记录已更新时重新读取 ref。

来源和归属是两个概念。origin 保存提出问题时的页面、节点、源码和示例状态；parentRef 表示问题树归属，由插件固定上下文决定。Agent 不提交坐标、父 ID、版本或独立幂等 ID。

## 按问题选择表达

- 先确定用户的具体困惑，以及需要看清的职责、关系或状态变化，再选择最小表达。源码节点和连线能讲清时直接使用；必要原因与限制用邻近短文字补充，不强制画图或按字数截断。节点只保留短 label，title 和 question 是历史元数据；阅读目标仍是实际源码。
- 生成式 UI 用于更合适的空间组织，或让操作揭示条件与结果的关系。先说明它帮助用户看清什么，再选组件；切换几段解释或展示虚构字段本身不足以增加交互。一个可操作实验回答一个具体问题。
- 需要同时比较的含义或职责保持同时可见，可以是同图的几个无边源码节点。按独立问题或流程分组；Tabs 用于互斥任务或无需同时观察的内容，延伸细节确有需要才折叠。不同职责不自动产生连线或大分组。
- 同组需要图、JSON、交互组件或示例时，用 Cluster 的 diagram 与 companion 插槽。整页共用一个画布，组件与节点一起缩放；不要额外复制源码快照到图下方。
- 流程、调用、条件和数据来源使用 Graph。概念是什么、各自有什么作用，可以是无边节点或并排组件。
- 多行代码和 JSON 用短入口打开 IDEA 原生只读编辑器标签。JsonView 保存点击时的数据与状态；CodeExcerpt 查看保存的源码片段，并可定位当前源码。入口只写“数据示例”“TagDO 结构”等用途，ID、演示名称和限制写在相邻说明中；少量数值或结果直接用 Text，不把每个字段做成代码入口。
- Card、Badge 的 tone 可为 neutral、info、success、warning、danger；用来标示信息、结果和风险，不给每个概念随机染色。正文保持正常颜色，含义也用文字说明。
- 缓存中的 JSON 文本应把 key、Redis 类型与 value 分开呈现：主入口 JsonView 显示明确解析后的值，次要入口用 format=text 保留原始字符串。只有已确认属于 JSON 的文本才提供解析视图；不能通过删反斜杠修改原文。
- 需要改变状态并观察结果，使用状态绑定的组件。确实需要自定义行为时再用隔离 Demo。
- 在 Cluster 内组合当前问题需要的组件，操作与反馈放在相关对象附近；生成页面与图表达相同信息时保留更直接的一种。继续使用整页统一画布。
- 教学独立短程序放入 codeSamples，以 CodeSample 或图节点 sample 在原生只读编辑器打开。项目实现仍用 sources；模拟值和路径明确标注，运行证据按需要获取。字段见协议。
- 同一函数保持同一名称；短标题不能把重命名伪装成新概念。
- 同名概念先区分职责、归属及真实关系，优先直接定位对应声明。字段、DTO、关联表、缓存表示只在回答当前疑问需要时补充；枚举码值不能证明尚未核实的行为区别。CodeExcerpt 适用于确有价值的源码快照对照，保留各文件的独立来源。
- 连线的 label 仅放区分分支必需的短条件，如“命中”“未命中”。参数、传递内容和重复动作说明写入 summary，按需查看；不把 kind 或 summary 当常驻标签，不重复节点文字。
- 先判断示例是否能帮助理解当前概念；只重复字段名或与问题无关时省略。确需示例时明确标注，例如在“数据示例”旁说明“7 是示例记录 ID，Redis 是示例名称”，不让示例取代概念和结构解释，不把它称为未经核实的请求或运行数据。
- 每个节点逐项核对表述与源码锚点：入口对应声明，分支对应条件，动作对应调用，返回对应实际返回语句。共享锚点须有相同语义依据，不为省事给不同动作复用整段函数。缓存/AOP 等拦截器可跳过方法体，命中行为应锚定其注解或拦截实现，不能借方法末尾的 return 证明命中。
- 只解释当前问题，不附带不相关流程。示例和推断不能写成实际运行记录。

需要组件与图联动时，给 Graph 设置独立 selectionPath；节点 ID 写入该 JSON Pointer，组件读取或写回同一路径。组件操作不能写不存在的节点 ID。不要把图内分组当作追问层级；继续问题时用插件提供的 note: 引用。

Graph 的节点可无源码，但实际项目实现的说法须能核对相应 sources。关系种类为 control_flow、call、data_flow、dependency、structure；推断关系提供 evidence 中的源码 ID 并标为 inferred。

## 待处理项

用户从插件复制的列表包含问题原文和 note: 引用。按列表顺序逐条读取引用、分析并提交对应回复；源码和组件状态从固定上下文获取。初始问题由用户在自己的 Agent 中提出，插件只展示答案、收集注释和导出待答问题。

lessplain_context 读取不清除 pending。逐条处理原问题，分别用其 note: ref 获取固定 context；提交成功后插件在同一事务保存回答及问题快照、删除待答行。回答仍在追问树中，原 note: 可重建历史引用；用户手动删除的待答引用失效。不能用完成反馈工具清除源码问题。

反馈可以触发页面修订或实现修复。处理完成后用 lessplain_finish_feedback(refs) 确认当前反馈引用；已编辑的旧 ref 会被拒绝。读取失败、提交失败或任务被取消时，不报告处理完成。

页面字段和 Demo 协议见 [协议](references/protocol.md)。需要持续教学时可由用户调用 lessplain-teach；它沿用本协议。
