# 规划与产品原则

本目录是代码理解插件的设计与交互试验。完整产品方案统一维护在 [主设计文档](../docs/for-agents/code-understanding-design-v0.5.md)，README 负责入口、运行方式与实现状态。不要重新建立相互补充、相互覆盖的多份主设计文档。

- 使用中文。当前是早期产品规划，目标是完成长期可用的软件。讨论设计时先检验用户意图、前提和取舍；发现问题要说明理由，不能一味认同或直接转成代码。
- 文档与回复尽量简洁，避免长篇 AI 说明；先给决定和具体例子，删除重复原则与过早的参数展开。读到用户批注时保留其修改，解释疑问后再整理。
- 明确区分产品目标、已确定的设计、待验证假设和原型已实现行为。当前环境、短期交付速度和演示便利不能决定长期架构；分阶段验证也不代表永久放弃能力。
- 尽可能开箱即用，沿用 JetBrains 的操作习惯。用户应能从界面判断功能用途与下一步，不必理解 token、父级参数或内部事件结构。
- 最低平台目标为 2026.1，长期面向 IntelliJ Platform 系列 IDE。原生“图表”体验为首选参考，优先验证 Diagram 复用；跨产品、语言和调试能力分别验证，不宣称未经验证的全面兼容。
- 一个 Understanding 主工具窗口容纳理解记录、问题图和项目关系图。源码使用原生编辑器，文件结构使用原生 Project Tree；不要把理解记录塞进 Project Tree 或拆成另一个插件窗口。
- 首次打开显示最近记录，完整历史通过按钮进入窗口内的独立历史页。问题图和项目图可主动打开到编辑器区域。目录说明默认自动显示已有结果，多职责默认一条；逐文件夹开关放右键菜单，不要求逐一配置。
- 以图组织关系和路径，避免重复的线性说明面板。保留必要的短标签、分支条件、证据和动作名称，不能为追求纯图形而增加猜测成本。
- diff 按变化类型选择原生文本或关系图，图必须能回到前后版本的实际代码。删除使用说明不等于删除工具；变化事实、影响和修改理由分别取证。
- 图、源码、diff 和解释使用一致的就地提问流程，回答后能回到原处。允许局部问题输入，不另建完整聊天产品；Agent 任务交接未实现前明确使用复制降级，不能假装已接通。
- 默认保存插件内的全部问答和理解结果，不让 Agent 判断是否值得保留。简短问答按所属问题或源码位置收纳，历史可展开、搜索并回到来源；需要新图或独立上下文才单建理解记录。保存与独立展示分开。
- 静态逐步探索到控制流分支时，由用户选择继续研究的路径；自由浏览不受限制。项目依赖关系不当作执行分支，选择路径不产生真实命中或运行值。
- 真实运行回放遵循记录，不能让用户的选择改写运行事实。代码变化、旧证据和未知状态都要可辨认，变化提示必须有查看依据与继续处理的入口。
- 重复节点默认显示命中次数，选中后在图内展开次数选择，选择后同步全图回放进度。编辑器只强调当前位置，不留累计高亮，不压暗其他代码。
- 演示场景、模拟 Agent 回答和接口调试控件不属于产品交互。外部任务动作只有在实际接通对应能力后才能出现，不用假按钮掩盖集成缺口。
- Project Tree 是陌生项目的默认全局入口。项目图以类似 UA、覆盖整个项目的全局图为目标，保留在首个完整可用版本内；聚合只控制显示细节，局部验证不缩减产品范围。UI Outline 延后；参数效果交给项目现有 Hot Reload／HMR，不自建跨框架预览或渲染器。
- 修改规划时同步主设计文档、README 的实现状态和相关 Agent 工作流；不把尚未完成的设计写成现有功能。用户只要求整理文档时，不擅自改前端。
