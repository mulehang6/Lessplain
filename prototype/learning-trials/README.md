# 两个小验证

先看分遍教程，再单独试目录导航。它们是验证材料，尚未接入插件的正式导航。

- `dist/reading.html`：每次只展开一遍阅读，正文、图和模拟与写入 Lessplain 的三份教程对应。
- `dist/navigation.html`：使用 mulehang-agent 的目录快照和只读源码，验证连续换文件后的位置感。
- `lessons.mjs`：教程与预设模拟的共同内容来源；`dist/lessons.json` 是构建时导出的结构化内容。模拟没有执行模型或工具。

生成与检查，不启动开发服务器：

```powershell
node learning-trials/build.mjs
node --test learning-trials/*.test.mjs
```

导航页可以直接双击打开。默认从 `chat/export/ConversationMarkdownExporter.kt` 开始；点 `state`，再切到 `shared`，最后用返回找回导出。也可以先记住导出的位置，换几处后不用返回按钮，直接在目录里找它。所有文件按目录、文件分别排序；切换只展开当前路径，邻居保留一行，返回恢复各区域和源码的滚动位置。

页面仅在当前浏览器保存阅读位置，可通过“重新开始”清除本实验的记录。它不读取 IDE 编辑器状态，也不操作原生 Project 窗口。源码是生成时的静态快照，浏览或点击不代表真实运行。

## 验收时看什么

1. 第一遍结束后，能否用自己的话说出“一句话怎样变成屏幕上的回复”？不要求记住类名。
2. 第二遍后，能否指出工具结果还要交回模型，随后才能继续回答？
3. 换了几个文件后，能否找回导出所在的目录，认出旁边的状态目录？

“记不住”“还是太多”“不知道下一步看哪里”都算有效反馈，不把打开次数或速度当成理解程度。

已验证的自动化行为与本轮结果见 [验证记录](../../docs/for-agents/learning-trials-2026-11-06.md)。
