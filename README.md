# Master Understanding

IntelliJ IDEA 2026.1 起兼容的插件；以 2026.1.5 编译，开发实例使用 2026.2.3。Agent 通过 IDE MCP 提交代码理解图；插件保存图和固定提问来源，并在工具窗口查看。产品目标与未实现范围见 [主设计文档](docs/code-understanding-design-v0.5.md)，Agent 工作流见 [配套 skill](skills/understanding-frames/SKILL.md)。

## 当前实现状态

- MCP 提供 `get_understanding_context` 和 `present_understanding`。插件保存的回答必须有图；画布只显示标题、图节点和关系。旧文字回答不再显示。节点注释作为待答追问保存；支持 `pendingNoteBatch` 时，Agent 一次读取当前理解图及其追问的全部待答注释，逐项使用原问题、`questionId` 和固定来源提交追问图。保存成功后同一事务删除独立注释条目，回答图保留原问题和来源，不另存已回答注释历史。
- 欢迎页、历史页与最近列表使用无前置图标的记录行；删除确认使用公开 DialogWrapper，由 IDE 绘制主题标题栏和标准按钮，初始焦点及默认动作为“取消”。待答注释的气泡常驻，点击打开全文，再次点击关闭，可编辑、删除或继续添加；无注释节点在悬停时显示添加入口。最近列表和注释展示使用 Jewel 弹层，注释与标题编辑使用跟随 IDE 主题的原生 Swing 文本组件和公开 JBPopup，支持中文 IME。注释展示、输入和按钮使用 IDE 外观的 UI 字体，不跟随编辑器字体；已打开的编辑面板响应外观字体变化。注释编辑支持 Enter 换行、Ctrl+Enter 保存，外部点击或 Esc 关闭保留当前画布中的草稿，取消丢弃草稿。有追问图的节点显示“？”入口，同一节点的追问图共用画布。分组标题提供悬停、按下与选中反馈，可点击铅笔或双击编辑，原始问题保留。
- 注释文本区固定宽度，默认一行，随换行和折行增高、删字缩回；最多 8 行并受可用屏幕限制，超出后内部滚动。顶部标题区域可拖动，内容变化保留移动后的位置。非空暂存草稿也常驻显示气泡：只有草稿时点击续写，已有注释与草稿共存时列表提供继续编辑。草稿仅在当前画布生命周期内保留，保存前不进入 Agent 待答队列，也不增加已保存注释数量。
- 根记录默认绘制单图，schema 4 可显式提交按职责划分的单层多 cluster，节点完整覆盖且互斥，真实跨组关系保留。组内和组间使用独立端口及通道，平行线路目标间距 12 逻辑像素，交叉使用跨线桥。短标题叠在画布内，与左上工具按钮同一行，不占独立高度；缩放、平移不会移动标题。悬停或键盘聚焦时，小铅笔紧跟标题末尾显示，支持双击及 Enter/F2 编辑。窄窗口截短标题，悬停显示全文。共享追问画布仍保持一问一组，分组导航和标题反馈继续可用；根语义分组标题通过图修订更新。
- 图由插件自身的 Swing 组件绘制，工具窗口与编辑器共用布局与绘制代码。业务起点蓝色，明确成功的结束点绿色，失败或预期拒绝的结束点红色，未知或混合结果的结束点使用中性色；双角色节点蓝底、按结束结果着色边框。角色由 `flowRoles` 明确指定，结果由可选 `endOutcome` 指定，不按图入度或出度推断。分支按 control_flow、call、data_flow 的不同后继数大于 1 自动显示橙色小图标，大小与文字一致，保持矩形节点；入度不参与，同目标平行边只算一个后继，不再提交 decision。聚焦和悬停使用外圈反馈。阅读路径高亮连线，移动虚线沿同一条曲线流动。图内有缩放、全图、一键整理、流动、固定源码跳转和自动跟踪节点开关，上下步在左下角。节点可手动拖拽，连线随之更新；一键整理保留当前横纵方向和方向偏好，只清除当前方向的手动位置。固定源码跳转后，选节点仍更新图，但不抢走图表焦点；关闭自动跟踪后，选节点不移动画布。工具窗口标题栏可将当前图在编辑器打开，编辑器中的追问会替换当前图页，标签使用短标题。`getParameter` 示例在流程图旁展示虚构的请求属性，点不同步骤会高亮对应的字段。
- 点击节点立即查看，展开所有能到达它的入口路径；优先使用业务 `start`，没有可达业务起点时使用自然入口或源强连通分量。上一步检查实际入边，下一步检查实际出边，只有多条候选时弹出条件菜单；平行边分别选择，已走过或记住的路线不替代本次选择。逐步浏览保留未决上游与已选后缀，直接点击任意节点重新展开。主动“选一条路线”可筛选完整候选、悬停预览并确认；左下“补全来路”和右键“重新选择来路”继续可用，补全期间目标与源码不变。方向键切换候选，Enter 确认，Esc 或空白点击取消；拖动画布不取消。合法长路线不受旧 100 步上限截断，重复访问仍有预算。共享追问的候选沿用原记录范围，根图跨 cluster 关系不受此限制。阅读路径不代表真实执行。
- SQLite 位于项目 `.idea/code-understanding/understanding.db`，保存问题、回答、固定来源、图版本及根记录的浏览状态。每条历史的根图、每个节点的追问图另有独立的项目本地视图状态，记录固定、跟踪、流动开关、当前路径、节点、缩放、视口中心和手动节点位置；工具窗口与编辑器共享这些设置。第二个实例只读；数据库迁移前备份，失败回滚。
- 选中有有效源码锚点的节点时，插件只在对应代码处添加一条 Understanding 提示，不改动其他插件的 Insight。提示右侧的上/下一步按钮优先操作当前画布的同一路线；画布选路期间暂停步进，没有可用画布时在提示处提供条件选项。悬停提示时，关联代码会出现短暂的渐变高亮；切换节点后清理本插件的旧提示。同一源码文件已在当前编辑器打开时，节点切换使用约 240 毫秒的平滑滚动，连续切换可中途改向，并遵守 IDE 的动画滚动设置；跨文件仍打开目标文件。固定源码跳转时，仅更新已经打开的源码编辑器。
- 源码定位使用当前文档内容，包括未保存编辑。重复文本不会自动认定为同一位置。定位结果在内部区分位置状态与证据状态；界面目前显示定位失败信息，完整的证据变化提示尚未完成。跨文件移动和依赖语义变化仍需更完整的语言适配与实测。

本批没有真实 Trace、完整 Diff 理解、项目全局图，也不接入 Agent 自动任务交接。当前只提供复制载荷的交接路径。

## 开发与安装

使用 JDK 21、仓库内的 Gradle Wrapper。在本目录运行：

```powershell
.\gradlew.bat test
.\gradlew.bat buildPlugin
.\gradlew.bat verifyPlugin --offline
```

安装包生成在 `build/distributions/`。在 IntelliJ IDEA 2026.1 或更新版本的 Settings → Plugins → Install Plugin from Disk 中选择 ZIP。插件依赖 IDE 自带的 MCP Server 和 Compose，不依赖 Diagrams。在 `Agent-dev` 工作区中选择 `Master Understanding IDE` 启动开发实例；若单独打开本目录，选择 `Master Understanding IDE (standalone)`。两项配置都执行本目录的 `runIdeLatest`，目前运行 2026.2.3。原有 `runIde` 仍运行 2026.1.5，供最低兼容版本复查；`sinceBuild=261` 保持不变，`verifyPlugin` 检查两个版本。若从终端运行 Gradle 命令，先进入本目录。自动化构建不会启动长期 IDE 进程。

## 使用流程

1. 图节点右键或悬停添加入口可添加注释；有注释时气泡常驻。Agent 调用 `get_understanding_context`，确认 `capabilities.pendingNoteBatch=true`，保存 `pendingBatch.scopeRecordId` 和 `items` 快照。队列只包含当前理解图及其后代追问中的待答节点注释，每项有自己的 `questionId`、原问题和固定 `context`，无需用户逐条选择。
2. Agent 用 `present_understanding` 逐项提交追问图，使用各项自己的原问题、`questionId` 和 `context.token`。成功项自动移除注释，失败或证据不足的项继续保留；最后用最初范围调用 `get_understanding_context(pendingScopeRecordId=…)` 复查，不随自动切换的画布改变范围。期间新加的注释保留到下一批。新记录须有实际图节点；工具不接受纯文字回答。当前使用 `schemaVersion=4`，兼容无 `clusters` 字段的版本 3 请求，根图可显式分组，追问继续一问一组。每次操作使用唯一 `requestId`，同 ID 同内容重试返回原结果，同 ID 不同内容报冲突。
3. 在 Understanding 工具窗口选择顶层记录，悬停并点击节点的“？”进入该节点的追问画布；画布包含该节点的全部问题 cluster，可用画布内的导航按钮跳转。只有节点确实有追问时才显示“？”。“返回”逐层退回，“层级”菜单可在整棵追问树中跳转。点击节点展开全部上游，按当前方向的候选边逐步浏览；`control_flow`、`call` 和 `data_flow` 连线均可导航，不依赖节点类型。

`present_understanding` 的 `graph` 参数是 JSON 字符串，形如：

```json
{"nodes":[{"id":"start","label":"检查输入","anchor":{"path":"src/Main.kt","symbol":"main","text":"if (valid)","version":"内容哈希","lineHint":12}},{"id":"yes","label":"继续保存"}],"edges":[{"id":"valid","from":"start","to":"yes","relation":"control_flow","condition":"valid=true","coverage":"当前分析范围"}],"evidence":[]}
```

图中的节点、关系和证据使用稳定 ID。`relation` 可为 `control_flow`、`call`、`data_flow`、`dependency` 或 `structure`；控制流分支与依赖关系分别处理。不要提交坐标。无来源的新记录需显式设置 `placement=root`，或使用 `placement=explicit` 并提供有效的 `parentId`。

节点 `flowRoles` 可为 `["start"]`、`["end"]` 或 `["start", "end"]`，普通节点省略或用空数组。可指定多个起点与结束点；`kind` 继续表示节点类别，不承担业务角色。协议当前为 4，兼容无 `clusters` 字段的版本 3 请求：仅当上下文返回 `capabilities.nodeSemantics=true` 时提交可选的 `endOutcome`，为 `success`、`failure` 或 null，非空时必须包含 end 角色。不确定或同一节点涵盖多个结果时保持 null；捕获异常后恢复执行不等于失败结束。分支由插件统一计算，不提交 decision，旧记录中的该字段由现有 JSON 读取机制忽略，不设置旧图分支逻辑。

开发 IDE 中已有真实 MCP 写入和手动界面试用。下一轮重点核对：从“最近”切换历史时标题、图和源码标识是否一起切换；每条历史及其追问层的固定、跟踪、路径和视口是否分别恢复；工具窗口与编辑器同时打开同一图时开关是否同步。自动化测试和 Plugin Verifier 不能替代这些界面检查。
